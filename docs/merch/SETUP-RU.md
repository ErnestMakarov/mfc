# Каталог формы MFC

Готово: `/merch`, 11 страниц `/merch/:slug`, 33 фотографии (основной и облегчённый размер), фильтры, увеличение фотографий, таблицы размеров, форма, переводы ET/RU/EN. Ссылка «Мерч» / «Klubivorm» / «Clubwear» стоит перед новостями в обоих меню хедера.

## EmailJS — сделать до публикации

1. В текущем аккаунте EmailJS создайте **новый** Email Template. Существующий шаблон записи на тренировки оставьте как есть.
2. В Content переключитесь на редактирование HTML / Code editor и вставьте целиком `docs/merch/emailjs-template.html`.
3. Установите поля шаблона:

| Поле | Значение |
| --- | --- |
| To Email | Реальный email заказчицы (фиксированный адрес) |
| Subject | `MFC ostusoov: {{product_name}} / {{product_size}} — {{customer_name}}` |
| From Name | `MFC veebileht` |
| From Email | Use Default Email Address / адрес подключённого сервиса |
| Reply To | `{{reply_to}}` |

4. Сохраните и скопируйте **Template ID** из Settings, например `template_abcd123`.
5. Установщик попросит Template ID и добавит его в `.env.local`. Если установку делаете вручную, добавьте:

```dotenv
VITE_EMAILJS_MERCH_TEMPLATE_ID=template_ваш_id
```

Используются уже подключённые в форме контактов Service ID `service_xfub9eq` и Public Key `1rWXEQCaKSIe2JqzW`. Если новый шаблон в другом аккаунте/сервисе, дополнительно укажите в `.env.local`:

```dotenv
VITE_EMAILJS_MERCH_SERVICE_ID=service_ваш_id
VITE_EMAILJS_MERCH_PUBLIC_KEY=ваш_public_key
```

Private Key в клиентский код не нужен. На хостинге добавьте эти VITE-переменные в Environment Variables проекта и заново выполните сборку/деплой: локальный `.env.local` не передаётся через Git.

В настройках EmailJS проверьте разрешённые домены: `https://www.finswimming.ee`, `https://finswimming.ee` и адрес локальной разработки при тестировании. Проверьте лимит писем своего аккаунта.

## Установка на Mac

Скачайте `mfc-merch-update.zip` в `~/Downloads`. Откройте **корень текущего проекта mfc** в терминале VS Code. После создания EmailJS Template выполните:

```bash
mfc_update_tmp="$(mktemp -d)" && unzip -q "$HOME/Downloads/mfc-merch-update.zip" -d "$mfc_update_tmp" && bash "$mfc_update_tmp/mfc-merch-update/install.sh" "$PWD"
```

Введите Template ID при запросе. Скрипт проверит совместимость изменяемых исходников, сделает резервную копию затрагиваемых файлов и `.env.local`, скопирует изменения, добавит Template ID, выполнит lint и build. Нужна та же версия Node.js, с которой собирается текущий проект (Vite 8: Node 20.19+ либо 22.12+), и установленные зависимости (`npm ci`, если их ещё нет). Новых зависимостей нет.

После успешной установки: `npm run dev`, открыть `/merch`. Если текущий dev-сервер уже запущен, перезапустите его после изменения `.env.local`.

Скрипт не коммитит и не публикует сайт. Если интеграционные файлы изменились после изученного коммита `4d6266d`, установка остановится до копирования и перечислит несовпадения. Это защищает ваши текущие изменения. Готовые файлы находятся в `payload/`; для такой версии нужно вручную перенести добавление маршрутов, namespace `merch`, пункта меню и переводов header.merch.

## Проверка после настройки реального шаблона

1. Выберите товар и размер, введите имя, фамилию и доступный email, подтвердите согласие, отправьте одну тестовую заявку.
2. Убедитесь, что заказчица получила письмо с нужными товаром, размером, цветом и данными покупателя.
3. Нажмите Reply в полученном письме: адресом ответа должен быть email покупателя.
4. Проверьте прямое открытие и обновление `/merch/men-hoodie` на хостинге. В проекте уже есть Vercel rewrite на `index.html`; на другом хостинге должен работать такой же SPA fallback.

Проверены данные 11 товаров, 33 фотографии, размеры поставщика, переводы, все 33 сочетания страницы товара и языка, фильтры, переходы галереи, неизвестный товар и 8 прежних маршрутов. Проверены обязательные поля, установка фокуса на ошибку, двойное нажатие, содержимое EmailJS-запроса, успешная отправка, ошибка с сохранением полей, отсутствие Template ID и honeypot. Визуальная проверка в настоящем браузере здесь заблокирована средой; перед публикацией просмотрите десктопную и мобильную версии.

В этой работе реальные письма не отправлялись: настройки нового шаблона и получателя доступны вам. Отправка проверяется с подменённым ответом API. Без Template ID форма показывает понятное сообщение и не отправляет запрос.

## Данные и изображения

- `src/data/merchProducts.js`: 11 товаров, размеры и файлы изображений.
- `src/i18n/locales/{et,en,ru}/merch.js`: названия, описания и тексты интерфейса.
- `src/config/merchEmail.js`: настройки EmailJS.
- `public/images/merch/`: основные WebP 1200×1600.
- `public/images/merch/thumbs/`: облегчённые WebP 600×800.
- `public/images/merch/size-guides/`: таблицы размеров из Photos.pdf.

Названия простые; модель поставщика передаётся в письмо. Размеры взяты из PK 260926.pdf; дополнительные размеры на таблицах не предлагаются, если их нет в предложении. На странице есть пояснение.

Цены предложения поставщика относятся к партиям по 10/15/20 штук и не являются утверждёнными розничными ценами. Поэтому на сайте указано «Цена уточняется». Каждая заявка относится к одному товару в одном размере, количество 1. Клуб согласует цену, оплату и получение при ответе.

Клиентская форма содержит проверку полей, honeypot и ограничение частоты в SDK. Это базовая защита, а не серверная проверка каталога; данные письма следует подтвердить перед оплатой.
